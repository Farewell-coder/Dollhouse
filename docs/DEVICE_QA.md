# Dollhouse · 真机验收清单

> **这份清单存在的原因**：整个 UI 重构到现在的判断**全部是静态的**。
> - 对比度是用 WCAG 公式**算**出来的，没有人用眼睛看过；
> - 聚焦态、阴影、骨架行、资料卡 —— **一次真机都没上过**；
> - 按钮手感、转场流畅度、触摸闸门是否真的放行 —— **完全未验证**；
> - 本机是 proot arm64 环境，没有 aapt2，`./gradlew` 跑不起来，所以连编译都没验过。
>
> **怎么用**：拿真机，按条目从上往下做。每条都有「在哪看 / 期望 / 判断标准 / 出问题说明什么」。
> 通过的打勾，不通过的记下机型 + 截图。
>
> **每条都标了来源**（commit 或文档）。没标的地方就写「未核实」——不编。

**建议准备**：至少两台机（一台 OLED + 一台 LCD），系统字体分别设 100% 与 130%，
主题分别试 浅色 / 深色 / 纯黑。

## 一、组件形态变化

### 1.1 行组件转发后的间距一致性

| # | 在哪看 | 期望 | 判断标准 | 出问题说明什么 |

## 二、颜色与对比度（**算出来的，需肉眼确认"看起来对"**）

> 对比度是 WCAG 公式算的（`tools/palette_contrast.py`），**公式达标 ≠ 看着舒服**。
> 尤其发丝线这类 1dp 元素，数值 1.37 在公式里"可辨识"，在强光下可能仍看不见。

### 2.1 发丝线三档（刻意比设计稿深一档）

来源：`ThemeManager.kt` 的 LIGHT/DARK/BLACK 注释块 + `docs/DESIGN_PARITY.md` 例外表。

| # | 在哪看 | 期望 | 判断标准 | 出问题说明什么 |
|---|---|---|---|---|
| 2.1.1 | **浅色**主题，设置页卡片之间 / 列表行之间 | 1dp 线**看得见**，但**不抢眼**（不该像表格边框那么重） | 距离屏幕 30cm 能分辨线；眯眼看整体不出"网格感" | 若几乎看不见 → 1.37 在强光下不够；若很重 → 加深过头 |
| 2.1.2 | **深色**主题同样位置 | 同上（暖炭底上的浅线） | 线可见且不发白刺眼 | 深色档 line 用了 `#38332A`；若发白说明取了设计稿的浅值或对比度夹紧过头 |
| 2.1.3 | **纯黑**主题 | 线在 #000 上仍可分辨 | 能看出卡片边界 | 纯黑档最易"全黑看不见" |
| 2.1.4 | 户外 / 强光下（任一档） | 线依然可辨 | 阳光下能否看清分隔 | **最可能翻车的一项**：1.37 是室内数值 |

### 2.2 气泡文字色

来源：`ChatUi.kt:674` 我方气泡用 `chatBubbleUser` 底，文字改 `c.title`。

| # | 在哪看 | 期望 | 判断标准 | 出问题说明什么 |
|---|---|---|---|---|
| 2.2.1 | 聊天页，**我发出的**消息气泡 | 深色文字压暖灰底，**不刺眼**、可长时间阅读 | 夜间看 5 分钟不累 | 若仍白字 → `chatBubbleUser` 改暖色后白字对比度会崩 |
| 2.2.2 | 同上，**对方**的气泡 | 与我的气泡**能一眼区分**（底色 + 描边不同） | 扫视一屏能分出谁说的 | 两者底色太接近 |
| 2.2.3 | 三档主题分别看气泡 | 深色/纯黑下气泡不与背景糊在一起 | 气泡边界清晰 | `chatBubbleUser` 在深色档为 `#2B2620`，与 `card #1E1B15` 很接近 |

### 2.3 未读徽标

来源：`ChatListScreen.kt:580`、`BottomNav.kt:185` 用派生色 `onErr`（按底色明暗自动选黑/白字）。

| # | 在哪看 | 期望 | 判断标准 | 出问题说明什么 |
|---|---|---|---|---|
| 2.3.1 | 聊天列表，有未读的会话 | 红底徽标上的数字**清晰可读** | 数字边缘不糊、不"吃进"红底 | `DesignSystem.kt:495` 的 onErr 选色逻辑失效 → 回到白字（暗色档只有 2.48:1） |
| 2.3.2 | **深色 / 纯黑**主题的未读徽标 | 深色字压浅红底（因为 err 在暗色档是**浅红** `#E58E77`） | 数字是**深色**的，不是白色 | 这是最容易看错的一项：直觉上"红底白字"，但这里必须反过来 |
| 2.3.3 | 底栏的红色角标（若有） | 同上 | | 同 2.3.2 |

## 五、按我的判断，最可能出问题的（排序）

> 以下是基于「改动幅度 × 静态检查的盲区 × 历史翻车记录」的判断，不是实测结论。

| 序 | 项 | 为什么最可能出问题 |
|---|---|---|
| **1** | **4.2.1 切 Tab 后表单内容是否还在** | slot 复用是**最容易静默失效**的一类：不崩、不报错，只是内容没了。而且它依赖 Compose 的重组身份，静态检查完全看不见 |
| **2** | **2.3.2 深色档未读徽标必须用深色字** | 与直觉相反（"红底白字"），且这个 bug 历史上**真实发生过**（暗色档白字只有 2.48:1）。改对了也可能被后人改回 |
| **3** | **4.4.2 / 4.4.5 触摸闸门** | 闸门是"少一层就隔层点击、多一层就点不动"的二元问题，静态检查只能看到"有 LayerShield"，看不到"是否真的拦住了"。`350f91e` 还刚修过 LayerShield 的 import 包路径错误 —— 说明这块确实脆 |
| **4** | **1.3.5 那 5 处 flat 卡有没有变成双层圆角** | `d21c267` 专门强调路由顺序（flat 必须先判），说明这个坑真实存在且只差一行顺序 |
| **5** | **2.1.4 发丝线在强光/户外下是否还看得见** | 对比度 1.37 是**室内计算值**。设计稿原值 1.20 被判定"看不见"才加深的，加深后是否够，只有户外能验 |
| **6** | **3.2.1 聊天主输入框聚焦态** | 它是 53 处输入框里**唯一漏过**的（`b9d4fdf`），且是最高频的输入位置。聚焦态接的是 `interactionSource`，漏传就静默恒 false |
| **7** | **4.1.4 聊天页草稿保命** | 去 View 时明确保留了 `onRetainNonConfigurationInstance` 的草稿能力，但这是「只在旋转/重建时触发」的路径，日常测试根本碰不到 |
| **8** | **1.2.5 禁用按钮是否真的拦点击** | 视觉禁用容易做（改 alpha），拦点击容易漏。漏了就是"点了没反应但发了请求" |
| **9** | **1.3.3b 模型面板仍用文字箭头** | 已确认是**尚未收编的真实残留**（`ChatPanels.kt:240`）。它与 DhGroup 的矢量箭头并排出现时，粗细与基线会对不上 —— 单看都不别扭，并排才明显 |

## 六、无法在本清单覆盖的

诚实标注：

| 项 | 为什么 |
|---|---|
| **编译是否通过** | 本机 proot arm64 无 aapt2，`./gradlew` 必然在 `processDebugResources` 失败。**整个重构从未编译过**，第一次真机安装才是真正的编译验证 |
| **性能 / 帧率** | 需要 Perfetto / GPU profiling，清单式人工检查看不到 |
| **无障碍完整走查** | TalkBack 的实际朗读顺序需逐页听，本清单只覆盖"有没有 contentDescription"这一层 |
| **多机型适配** | 本清单基于 390×844dp 设计基准；窄屏 320dp / 平板 / 折叠屏未覆盖 |
| **深色下的背景图叠加** | 用户自定义背景图 + 卡片透明度组合是组合爆炸，需单独测 |

## 附：快速自检顺序（约 15 分钟）

若时间有限，按这个顺序做，覆盖风险最高的部分：

1. 打开聊天页 → 能显示、不闪退（4.1.1）
2. 聊天页输入框点一下 → 有描边（3.2.1）
3. 深色主题 → 看未读徽标数字是不是**深色**（2.3.2）
4. 设置 → 供应商 → 编辑 → 填字 → 切页签 → 切回 → **字还在吗**（4.2.1）
5. 设置页展开一张卡 → 退出重进 → **还是展开吗**（4.3.1）
6. 打开抽屉 → 点抽屉外面 → **有没有误触下层**（4.4.2）
7. 点任何一个按钮 → 有没有涟漪（不该有）（1.2.4）
8. 三档主题各看一眼发丝线（2.1.1~2.1.3）
