  | chip | bounds | 宽 | 与前一 chip 间距 |

  宽度分解验证：`170 = 文本 72 + 左 36 + 右 36 + 26`。

### ✅ 已证伪 · dump 测量基准问题：顶栏「整块 −6dp」不存在（**不要按它改代码**）

> **本条由 `ui-impl` 查清、我已用项目源码独立复核确认。原判定「顶栏比内容区左移 6dp」是错的。**

**根因**：`uiautomator dump` 给的是**无障碍边界**，不是布局边界。
Compose 的无障碍桥会把**小于 48dp（= `DhKit.MIN_TOUCH`）的语义节点，以元素中心为基准对称外扩到 48dp**。
我量到的 `x=30 / y=24` 是外扩后的框，不是布局位置。

**逐像素复核（我自己算的，与 dump 完全吻合）**

| 项 | 数值 |
|---|---|
| 头像源码尺寸 | `DhDesign.Size.avatarTopBar = 36.dp`（`DesignSystem.kt:286`） |
| 布局尺寸 | `36dp × 3 = 108px` |
| 无障碍框 | `48dp × 3 = 144px` |
| 每边外扩 | `(144 − 108) / 2 = **18px**` |
| 布局左缘应为 | `48px`（`PAD_PAGE = 16dp`） → 外扩后 `48 − 18 = **30**` ✅ 与 dump `x=30` 一致 |
| 布局右缘应为 | `48 + 108 = 156` → 外扩后 `156 + 18 = **174**` ✅ 与 dump `x=174` 一致 |
| 布局上缘应为 | `42px`（`TAB_BAR_TOP = 14dp`） → 外扩后 `42 − 18 = **24**` ✅ 与 dump `y=24` 一致 |

**结论**：顶栏视觉左边缘**就是 48px = 16dp**，与搜索框（`[84,168][996,312]`）、会话卡片（`[48,492][1032,696]`）**本来就是对齐的**。
`PAD_PAGE = 16dp`、`TAB_BAR_TOP = 14dp` 两个常量一直是正确的 —— 我原报告里「源码 16dp 与实测 10dp 矛盾、疑似装饰层吃掉 6dp」的推断**完全不成立**，是我误读了 dump。

**补充证据（`ui-impl` 复核，两条独立于上面的算法，不依赖同一假设）**

1. **同一行里找一个 ≥48dp 的元素，用它的位置反证布局没动。**
   实测 dump 里标题「聊天」节点 `x=192`。按源码：`48`（`PAD_PAGE=16dp`）+ `108`（头像 36dp）+ `36`（`Space.md=12dp` 间距）= **192** ✅。
   两个替代假设都会被这一条否掉：
   - 若顶栏整体左移 6dp → 标题应在 `186`（实测不是）；
   - 若头像真占 48dp（=144px）→ 标题应在 `228`（实测不是）。
   → **布局边界与源码逐像素一致，偏移只存在于无障碍框。**

2. **机制在库层面坐实（不是推测"可能是 Compose"）。**
   本工程 `app/build.gradle` 用 `compose-bom:2026.01.01` → `androidx.compose.ui:1.10.2`。解开该 artifact 的 `classes.jar` 可见：
   - `androidx/compose/ui/node/SemanticsModifierNodeKt` 同时导出 `touchBoundsInRoot` 与 **`useMinimumTouchTarget`**；
   - `androidx/compose/ui/semantics/SemanticsNode` 有 `getTouchBoundsInRoot`（布局边界另有 `getBoundsInRoot`）；
   - `androidx/compose/ui/node/DpTouchBoundsExpansion` 存在。
   即：**无障碍桥报给系统（以及 `uiautomator`）的是 `touchBoundsInRoot`，默认按最小触摸目标外扩到 48dp**；纯布局边界 `boundsInRoot` 才是 36dp。实测 144px / 8dp 每边外扩，与之吻合。

**为什么不能"修"**：要去掉这 6dp 只有两条路 ——
① 把 36dp 头像改成 48dp（视觉变大、顶栏变高）；
② 删掉 48dp 触摸区（违反 M3 无障碍、小元素容易点空）。**两条都是倒退。**

**后续所有用 dump 量位置的工作，必须先做这个换算（写进方法论）**

```
当被量元素 < 48dp 时：dump 的 bounds 以元素中心为基准，对称外扩到 48dp
    布局值 = dump值 ∓ (48dp − 元素实际尺寸) / 2      // 左/上减，右/下加
```
判断"布局有没有真的偏"的**正确做法**：量同一行里一个 **≥ 48dp 的元素**（卡片左边缘、搜索框），它的 dump bounds 是可信的。

**本条遗留的有效信息**：只有下面这一点仍然成立 ——

- **头像圆底边 y=168 与搜索框顶边 y=168 相接（0–1px）**：头像布局 42..150、搜索框 168..312，实际间距 **18px = 6dp**，不是 0。**这条也一并作废**（同样是被外扩框骗了）。
- 唯一仍然成立的是**可访问名缺失**（见下一条 P2），那条与几何无关。
