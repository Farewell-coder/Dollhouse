### [P2·**源码已修**] 聊天列表 · 筛选条选中态用「 ·」后缀表达，切换时整行 chip 横向跳动 26px

> **状态更新（07:46 后发现）**：本条已被 `c176669 fix(ui): 筛选条改用真选中态（去掉像坏角标的「·」）+ 药丸内容居中` 修掉，
> `ChatListScreen.kt:265-267` 现在是 `DhKit.OutlineChip("全部", selected = filter == 0)`。
> **但装机 APK 是 07:40 编的，不含此修复** —— 所以真机上仍能测到 26px 跳动（本条的 bounds 就是证据）。
> 若要在真机上复验，需要重新装一次。**不要再重复改这段代码。**

- **现象**：选中项比未选中项**宽 26px（8.67dp）**。点到某个 chip 上时，它自身与它右边所有 chip 都会整体位移 26px —— 手指正下方的点击目标会跟着跑。
- **证据**（`/tmp/v/w1.xml` 原始 bounds）：

  | chip | bounds | 宽 | 与前一 chip 间距 |
  |---|---|---|---|
  | 全部（选中） | `[48,324][218,468]` | **170** | — |
  | 未读 | `[242,324][386,468]` | 144 | 24 |
  | 置顶 | `[410,324][554,468]` | 144 | 24 |
  | 归档 | `[888,324][1032,468]` | 144 | 334（见 §2 已排除） |

  宽度分解验证：`170 = 文本 72 + 左 36 + 右 36 + 26`。
  其中 `左/右 36px = 12dp`，与源码 `padding(horizontal = 12.dp)` **逐像素吻合**；`文本 72px = 2 字 × 12sp × 3`，与 `UiKit.FS_CHIP = 12.0f` 吻合 → 说明 26px 差额**只来自文案多出来的「 ·」**。
- **源码定位**：`app/src/main/java/com/dollhouse/app/ui/chat/ChatListScreen.kt:265-267`
  ```kotlin
  DhKit.OutlineChip(if (filter == 0) "全部 ·" else "全部") { filter = 0 }
  DhKit.OutlineChip(if (filter == 1) "未读 ·" else "未读") { filter = 1 }
  DhKit.OutlineChip(if (filter == 2) "置顶 ·" else "置顶") { filter = 2 }
  ```
  而 `DhKit.OutlineChip` **已经有 `selected: Boolean` 形参**，其 KDoc 原文就写着这段拼接是"粗糙做法 / 选中态应该靠底色与字色表达"（`ui/compose/DhKit.kt`，`OutlineChip` 定义处，参数 `selected` 上方注释）。体检当时"迁移写好了但调用点没改"，07:46 的 `c176669` 已补上。
- **建议修法**：4 个调用点改成
  ```kotlin
  DhKit.OutlineChip("全部", selected = filter == 0) { filter = 0 }
  ```
  删掉三处字符串拼接。改完 chip 宽度恒定 144，整行不再跳。零结构改动。
- **截图**：无（只读模式，见 §0）

### [P2] 聊天列表 · 搜索框的可访问名（placeholder）在无障碍语义里丢失

- **现象**：dump 里搜索框节点为 `EditText class=android.widget.EditText text='' desc=''`，而源码给的 hint 是"搜索会话或人偶名"（`ChatListScreen.kt` 搜索框 `hint = "搜索会话或人偶名"`）。placeholder 由独立 Text 绘制，不进 TextField 的语义 → 读屏软件只会念"编辑框"。
- **证据**：`<node class="android.widget.EditText" text="" content-desc="" bounds="[84,169][996,313]" clickable="true">`，无 `hint` 属性、无 content-desc。
- **同类**：本页 6 个 clickable 节点全部 `content-desc=''` —— 头像入口（`[30,24][174,168]`，`Image contentDescription = null` + `Icon` 无 desc）、4 个筛选 chip、会话卡片。读屏只能念出 chip 的文本（还算可用），**头像抽屉入口完全无名**。
- **建议修法**：给 `DhForm.Input` 加 `Modifier.semantics { contentDescription = hint }`；给头像 Box 加 `Modifier.semantics { contentDescription = "我的资料" }`。

### ✅ 已排除：底栏选中项图标 152×152 ≠ 未选中 144×144 —— 是 1.06 选中放大，不是两套口径

- **数据**：`聊天 icon (286,2183)-(438,2335)` = **152×152**；`人偶 (468,2187)-(612,2331)` = 144×144；`说说 (646,2187)-(790,2331)` = 144×144。
- **判定依据**：`ui/home/BottomNav.kt:121-125`
  ```kotlin
  val scale by animateFloatAsState(
      targetValue = if (selected) 1.06f else 1.0f, ...)
  ```
  且该值作用在 `graphicsLayer(scaleX = scale, scaleY = scale)`。数值验证：`144 × 1.06 = 152.6 → 152` ✓ 精确吻合。
  144px = 48dp 是 `DhKit.MIN_TOUCH = 48`（`minTouchTarget()` 的 `sizeIn(minWidth/minHeight)`）给出的**命中区**，其中只有 `SZ_MD = 20dp` 是字形。
- **结论**：uiautomator 报的是**变换后**的命中区，选中放大 6% 是设计意图。**不要改。**


### ✅ 已排除：`置顶` 与 `归档` 之间 334px 空档不是"缺了一个 tab"

- **数据**：4 个 chip 齐全，bounds 为 `全部[48..218] / 未读[242..386] / 置顶[410..554] / 归档[888..1032]`，间距 **24 / 24 / 334**。
- **判定依据**：间距**并不均匀**（不是 334/334/334），所以"均分所以正常"不成立；但同时源码里「置顶」和「归档」之间正好有一句
  `Spacer(Modifier.weight(1f))`（`ChatListScreen.kt:268`），
  即「归档」被**故意推到行尾右对齐**，与「返回」按钮同位置。→ **设计如此，非缺陷**。
- 数值自洽：`554 + 334 = 888`，且归档右缘 1032 = 内容右缘 ✓。

### ✅ 已排除：`全部 ·` 不是"未读数角标没渲染出来"

### ✅ 已排除：底栏图标与文字"重叠 36–40px"
