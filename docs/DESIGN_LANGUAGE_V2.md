# Dollhouse · 设计语言 V2（Soft Neumorphism + Glassmorphism）

> **本文替代「安静居所」方向。** 旧方向的问题是层级靠发丝线 + 留白承担，
> 视觉上「平」——用户原话「说是说变得精致，可是我并没看到什么变化」是对的。
>
> V2 换成**轻拟物**：立体感来自**明暗关系**（亮面/暗面/投影），不是来自线条。
> 这是"一眼能看出变化"的方向。
>
> 所有数值都经过**对比度实算**（WCAG 公式），不是凭感觉填的。
> 复算脚本见文末附录。

---

## 0. 一句话概括这套语言

**「雾面玻璃上的浮雕」**：底色是浅蓝雾白，卡片像一块被磨圆、微微浮起的玻璃，
左上有一道柔光、右下有一层柔影，图标躺在浅色圆底里，文字清晰压在最上层。

三条铁律：
1. **立体感只从明暗来**（不用发丝线做主要层级手段）
2. **对比度不妥协**（正文 ≥4.5，标题 ≥7，发丝线 ≥1.3）
3. **深色是独立设计**，不是浅色的反转

| | 值 | 相对亮度 L |

## 2. 深色模式（独立设计，**不是反转**）

### 2.1 ⚠️ 为什么不能反转（附实算证据）

| 若直接反转浅色 | 结果 | 问题 |
|---|---|---|
| `bg` 变深、`card` 也变深 | 卡片与底**分不开** | 轻拟物靠"卡片比底亮"，反转后两者都暗，浮起感消失 |
| `accent #2F66C9` 直接用 | 深底上对比过高、发暗 | 深底上的饱和蓝**刺眼且不协调**（需换成 `#7AA7F5` 提亮降饱和） |
| 用浅色的白投影 `#FFFFFF` | 落在 `#222935` 上得到 **`#858990`** | **惨白发灰** —— 这就是用户说的"脏" |
| 用浅色的 `line #C9D6E4` | 在深底上是**亮线** | 反过来成了"发光边框" |

**结论**：深色必须重新选色——底色换冷蓝灰、卡片比底**亮**（维持浮起）、
强调色**降饱和提亮度**、投影换色（见 §5）。

### 2.3 关键差异总结（浅 vs 深）

| 维度 | 浅色 | 深色 | 为什么不同 |
|---|---|---|---|
| 卡片相对底 | 卡片**更亮** L+6.6 | 卡片**更亮** L+0.8 | 方向一致（浮起），但幅度必须小——深色下大亮度差会"糊成灰" |
| 输入框相对底 | **更深** | **更深** | 内凹语义不变 |
| 强调色 | `#2F66C9`（饱和） | `#7AA7F5`（浅、降饱和） | 深底上高饱和会发光刺眼 |
| `onAcc` | 白字 | **深字** `#0E1420` | 深色 accent 变浅后必须压深字 |
| 亮投影 | `#FFFFFF` | **`#3C4A5C`** | 白投在深底会变惨灰 |
| 暗投影 | `#9DB2C9` | **`#05080D`** | 浅色不能用近黑（会成灰块） |

## 3. 渐变背景

### 3.1 浅色：两段线性渐变（对角）

```css
background: linear-gradient(160deg, #EDF2FA 0%, #E9EFF7 45%, #E2EAF4 100%);
```

| 层 | 色 | 位置 |
|---|---|---|
| 起 | `#EDF2FA` | 左上（略亮，模拟"光从左上来"） |
| 中 | `#E9EFF7` | 45%（基准色） |
| 止 | `#E2EAF4` | 右下（略暗，承接投影） |

**方向 160deg**（左上→右下）——与 §5 的亮投影方向**必须一致**，
否则光影逻辑自相矛盾，大脑会觉得"不对但说不出哪不对"。

### 3.2 深色：两段 + 一点冷光

```css
background: linear-gradient(160deg, #1E2833 0%, #1A2029 50%, #161B24 100%);
```

深色同样是 160deg，但**亮度跨度更小**（避免大面积明暗断层）。

### 3.3 需要几层

**2 层**
1. **渐变底**（`Modifier.background(Brush.linearGradient(...))`）—— 全局铺一次
2. **可选：极淡径向高光**（左上角落，`radialGradient`，alpha ≤6%）——
   只在"首页/空状态"这类大面积留白页启用，列表页**不要**（会增加滚动开销）

**不要超过 2 层**。叠 3 层以上会变成"设计感过剩"。

## 4. 圆角体系（比现在更大）

| 用途 | 新值 | 旧值 | 变化 | 理由 |
|---|---|---|---|---|
| **大卡片** | **24dp** | 16 | +8 | 轻拟物的大圆角是「软」的来源 |
| **中卡片/弹层** | **20dp** | 16 | +4 | |
| **按钮** | **16dp** | 12 | +4 | 圆润轻量 |
| **输入框 / 搜索框** | **18dp** | 12 | +6 | 搜索框要"胶囊感"但不全圆 |
| **图标圆底** | **全圆**（999） | 8~12 | — | §6 统一为圆 |
| **药丸 / chip** | **999** | 999 | 不变 | |
| **缩略图** | **14dp** | 8 | +6 | |

### 4.1 与现有 4 档令牌的映射（兼容）

现有 `Radius { sm=8, md=12, lg=16, pill=999 }` 需要**扩成 5 档**：

```kotlin
object Radius {
    const val xs = 14    // 缩略图（新增）
    const val sm = 16    // 按钮（由 8 改 16）
    const val md = 20    // 中卡片 / 弹层（由 12 改 20）
    const val lg = 24    // 大卡片（由 16 改 24）
    const val xl = 28    // 特大（新增，全屏 sheet 顶角）
    const val pill = 999
}
```

**注意**：`sm` 从 8 改到 16 是**语义替换**（8 原本给缩略图/小标签，那些改用 `xs=14`）。
改之前要清点 `Radius.sm` 的所有调用点。

### 4.2 比例律（避免 §三 那类问题）

| 元素尺寸 | 圆角 | 比例 |
|---|---|---|
| ≤32dp | 全圆 或 10~12 | ≥0.35 |
| 40~56dp | 14~16 | 0.28~0.35 |
| 56~120dp | 20~24 | 0.20~0.30 |
| ≥120dp（大卡） | 24~28 | 0.15~0.22 |

## 5. ⭐ 阴影配方（轻拟物的核心）

### 5.1 原理

轻拟物 = **同一个元素身上有两种投影**：
- **亮投影**（左上）：模拟光源打过来
- **暗投影**（右下）：模拟自身遮挡

两者**都必须存在**，少一个就退回"普通投影"或"普通发亮"。

### 5.2 浅色模式配方

| 用途 | 亮投影（左上） | 暗投影（右下） |
|---|---|---|
| **卡片** | `-6dp -6dp 16dp #FFFFFF @45%` | `6dp 6dp 20dp #9DB2C9 @28%` |
| **按钮** | `-3dp -3dp 8dp #FFFFFF @55%` | `3dp 3dp 10dp #9DB2C9 @32%` |
| **输入框（内凹）** | `inset 2dp 2dp 6dp #C3D2E2 @35%` | `inset -2dp -2dp 6dp #FFFFFF @70%` |
| **浮层/弹窗** | `-8dp -8dp 24dp #FFFFFF @40%` | `10dp 12dp 32dp #8FA6BF @30%` |

> **输入框是反的**：轻拟物里凹槽的内阴影方向与凸起相反。
> 亮面在**右下**（凹进去后右下是被光照到的内壁）、暗面在**左上**（被自己遮挡）。

**Compose 实现注意**：`Modifier.shadow()` **不支持** inset，也不支持双投影。
需要：
1. 双投影 → 两层 `Modifier.shadow()` 叠加（Compose 1.10 支持多次 shadow）
2. inset → 用 `drawBehind` 手绘，或用 `Modifier.border` + 渐变模拟
   （见 §8「实现代价」）

### 5.3 ⭐ 深色模式配方（必须换色，否则脏）

| 用途 | 亮投影（左上） | 暗投影（右下） |
|---|---|---|
| **卡片** | `-6dp -6dp 16dp #3C4A5C @55%` | `6dp 6dp 20dp #05080D @60%` |
| **按钮** | `-3dp -3dp 8dp #44546A @50%` | `3dp 3dp 10dp #05080D @55%` |
| **输入框（内凹）** | `inset 2dp 2dp 6dp #0A0F16 @50%` | `inset -2dp -2dp 6dp #33404F @45%` |
| **浮层/弹窗** | `-8dp -8dp 24dp #43536A @45%` | `10dp 12dp 32dp #000000 @65%` |

### 5.4 为什么深色必须换色（实算证据）

| 组合 | 结果 | 判定 |
|---|---|---|
| 深色卡片 `#222935` + **白投** `#FFFFFF@45%` | 呈现 **`#858990`** | ❌ **惨白发灰** ← "脏"的量化来源 |
| 深色卡片 `#222935` + **亮灰投** `#3C4A5C@55%` | 呈现 **`#303B4A`** | ✅ 柔和提亮 |
| 浅色卡片 `#F2F7FC` + **近黑投** `#05080D@60%` | 呈现 **`#64686D`** | ❌ **灰块**，失去透明感 |
| 浅色卡片 `#F2F7FC` + **蓝灰投** `#9DB2C9@28%` | 呈现 **`#DAE4EE`** | ✅ 柔和压暗 |

**规律**：
- 浅色的暗投影**不能用黑**，要用**带蓝的灰**（`#9DB2C9`）——纯黑会让边缘"脏"
- 深色的亮投影**不能用白**，要用**带蓝的灰**（`#3C4A5C`）——纯白会让表面"发灰"

### 5.5 阴影克制度

| 场景 | 要不要阴影 |
|---|---|
| 大卡片 | ✅ 双层 |
| 浮层/弹窗 | ✅ 双层（加强） |
| 按钮 | ✅ 双层（轻） |
| 输入框 | ✅ inset |
| **列表行** | ❌ **不加**（性能 + 视觉噪音） |
| **文字/图标** | ❌ |

## 7. 字体（保留 8 档阶梯，只调字重配比）

### 7.1 现状问题

现在 8 档里 **6 档是 SemiBold(600) 或 Normal(400)**，中间只有 Medium 一档，
层次不够细。轻拟物需要**更细的字重对比**（标题要紧、正文要松）。

### 7.2 新配比

| 档 | 字号 | 行高 | 旧字重 | **新字重** | 变化 |
|---|---:|---:|---|---|---|
| `brand` | 22 | 30 | 600 | **600** | 不变 |
| `display` | 28 | 36 | 600 | **700** | ↑ 更"有个性" |
| `title` | 20 | 28 | 600 | **600** | 不变 |
| `section` | 16 | 22 | 600 | **600** | 不变 |
| `body` | 15 | 24 | 400 | **400** | 不变（正文必须清晰） |
| `sub` | 13 | 20 | 400 | **400** | 不变 |
| `caption` | 12 | 17 | 400 | **500** | ↑ 弱化但更清晰 |
| `label` | 11 | 16 | 600 | **500** | ↓ 减弱，避免小字过重 |

**改动只有 2 处**（display 700、caption 500、label 500），**字号行高全部不变**
——这样不会引发连锁的布局变化。

### 7.3 字体族

- **标题/品牌**：保留霞鹜文楷（`FontFamily` 已有）——"适度的个性"
- **正文**：系统无衬线（`FontFamily.Default`）——"必须清晰"
- **数据/代码**：`FontFamily.Monospace`（已有）

> ⚠️ **`PAL_SIZE = 29` 是硬校验**（`cachedMonetPalette()` 会因长度不符整体丢弃 Monet）。
> 加 `warn` 需要**同步改 PAL_SIZE 为 30**，并改 `ThemeManager` 三个数组 + `UiKit.snapshotPalette()`。
> 这是一处**有风险的连锁改动**，建议：**先不加 warn**，`warn` 暂用 `hintFg` 顶替，
> 等 V2 落地稳定后再单独一轮加槽位。

### 8.2 Radius：4 档 → 6 档

见 §4.1。**`sm` 语义变更**（8→16）需清点调用点。
若不想动，可改为 **新增 `xs` 而 `sm` 保持 8**，让按钮/输入框直接用 `xs`/`md` ——
**推荐后者**，改动面小。

### 8.3 Elevation：0/1/2 → 新增双投影结构

现有 `Elevation { e0=0, e1=2, e2=12 }` 是**单值**，装不下"亮投 + 暗投"。
建议改为：

```kotlin
object Elevation {
    // 保留旧值（向后兼容，现有 shadow 调用不变）
    val e0 = 0.dp
    val e1 = 2.dp
    val e2 = 12.dp

    // V2 新增：轻拟物双投影参数
    object Neu {
        val cardLightOffset = (-6).dp; val cardLightBlur = 16.dp; val cardLightAlpha = 0.45f
        val cardDarkOffset = 6.dp;     val cardDarkBlur = 20.dp;  val cardDarkAlpha = 0.28f
        // …按钮 / 输入框 / 浮层同构
    }
}
```

### 8.4 必须接受的一个现实：`Modifier.shadow` 装不下轻拟物

| 需求 | Compose 原生能力 |
|---|---|
| 双投影（亮+暗） | ⚠️ 可叠两次 `Modifier.shadow()`，但**只有暗色调**（elevation 只能压暗） |
| **亮投影（提亮）** | ❌ **不支持** —— `shadow()` 只画黑色投影 |
| inset 内阴影 | ❌ 完全不支持 |

**这意味着**：真正的轻拟物需要**自绘**——

```kotlin
// 方案：drawBehind 手绘双向渐变边
Modifier.drawBehind {
    // 左上亮边（线性渐变 白→透明）
    drawRoundRect(brush = Brush.linearGradient(listOf(white45, transparent),
        start = Offset(0f,0f), end = Offset(size.width*0.6f, size.height*0.6f)), ...)
    // 右下暗边（线性渐变 透明→蓝灰）
    drawRoundRect(brush = Brush.linearGradient(listOf(transparent, blueGray28),
        start = Offset(size.width*0.4f, size.height*0.4f), end = Offset(size.width, size.height)), ...)
}
```

**代价评估**：
- 每个卡片多 2 次 `drawRoundRect`，列表里 20 张卡片 = 40 次额外绘制
- 需要**实测帧率**，若掉帧则降级为"单层暗投影 + 1dp 亮边"

## 附录：复算脚本

```python
def lum(h):
    h=h.lstrip('#'); r,g,b=[int(h[i:i+2],16)/255 for i in (0,2,4)]
    f=lambda v: v/12.92 if v<=0.03928 else ((v+0.055)/1.055)**2.4
    return 0.2126*f(r)+0.7152*f(g)+0.0722*f(b)
def cr(a,b):
    la,lb=lum(a),lum(b); hi,lo=max(la,lb),min(la,lb); return (hi+0.05)/(lo+0.05)

# 浅色
print('title/card', cr('#22303F','#F2F7FC'))   # 12.47
print('sub/card  ', cr('#566A80','#F2F7FC'))   # 5.17
print('label/card', cr('#5A6E82','#F2F7FC'))   # 4.89
print('line/card ', cr('#C9D6E4','#F2F7FC'))   # 1.37
# 深色
print('title/card', cr('#E8EEF7','#222935'))   # 12.53
print('sub/card  ', cr('#9FB0C4','#222935'))   # 6.60
print('label/card', cr('#8899AD','#222935'))   # 5.02
print('line/card ', cr('#33404F','#222935'))   # 1.38
```

全部数值均以此脚本实算，非估算。
